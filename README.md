# Pi Run Trace

Pi 1.2.0 的运行流程扩展。按用户任务记录模型轮次、工具调用、嵌套关系、参数、结果、耗时、错误、压缩和等待输入。

## 安装与使用

需要 Node.js 22.19+ 和 Pi 1.2.0。

```sh
pi install git:github.com/tangf-ai/pi-run-trace
pi
```

本地开发时也可克隆后安装：

```sh
git clone https://github.com/tangf-ai/pi-run-trace.git
cd pi-run-trace
npm ci --ignore-scripts
pi install .
```

先给 Pi 一次任务，再输入 `/trace`，自动打开本机浏览器查看器。

- `/trace` 或 `/trace open`：打开查看器。
- `/trace on`：启用记录，默认已启用。
- `/trace off`：暂停记录，保留历史。
- `/trace path`：显示记录目录。

查看器左侧选择请求，中间点击流程节点，右侧查看输入输出、关联源码或针对节点提问。提问发送到当前 Pi 会话，使用当前模型；运行中的提问按 followUp 排队。

左侧请求历史按 `sessionId` 折叠分组：以该会话当前可见的最早请求作为标题，显示目录、日期、会话标识和请求数。会话按最近活动排序，默认展开选中或正在运行的会话，并保留手动折叠状态。不同会话即使目录相同也不会混在一起。节点详情使用紧凑信息行；宽面板将六项指标排成一行，窄面板自动换行。父节点显示可读名称，悬停可查看完整标识。

执行流程使用紧凑纵向时间轴：按真实开始时间排序，每步显示相对任务开始的时间、状态和耗时，工具按父子关系缩进。时间条使用整次请求的共同时间范围，位置表示开始时间，长度表示耗时，因此并行步骤能看到重叠。长任务在时间轴内独立滚动；“定位当前步骤”跳到最近开始的运行步骤，结束后可定位选中步骤。点击任意一行仍在右侧查看详情，刷新时保留选择与滚动位置；缺少结束时间的中断步骤不补造耗时。

使用已有的 Pi 源码提供关联代码：

```sh
PI_RUN_TRACE_SOURCE_ROOT=/path/to/pi pi
```

在 Pi 源码目录或与本扩展同级的 `pi` 源码目录中，扩展也会自动查找源码。关联的是阶段对应函数的源码节选，不代表函数内部每个分支都已被追踪。

## 记录方式

只订阅官方扩展事件，不替换 fetch，不修改模型请求或工具结果。以 `agent_settled` 判断任务最终结束，因此多个循环和自动续跑可以保留在同一任务中。通过 `parentToolCallId` 关联嵌套工具。

记录默认保存在 `~/.pi/agent/run-trace/runs/`，尊重 `PI_CODING_AGENT_DIR`。每条轨迹独立保存，文件权限为 0600。查看器绑定 127.0.0.1 的随机空闲端口，随当前 Pi 进程关闭；历史文件保留，重新打开查看器可回看。多个 Pi 进程各自拥有查看器，历史目录共用。

参数与结果在本机记录，已知凭证字段隐藏，图片数据省略，长内容截断；每个请求最多 512 个节点。HTTP 请求尝试只在 provider 发出相关官方事件时记录，缺失时不推断请求次数。实时页面显示节点状态，完整回复和工具结果在完成时显示。并行工具按父子关系分组，耗时是节点自己的耗时，不能相加作为任务总耗时。

本扩展的命令入口为 `/trace`。

## 内容预览与检索

输入、输出和模型请求尝试支持两种查看方式：默认以折叠树预览 JSON 层级，或切换到缩进格式化的 JSON。长字符串可以单独展开，以保留真实换行阅读提示词和工具输出；完整的 JSON 字符串会自动解析为结构预览。

搜索框支持字段名和内容的字面搜索，搜索结果自动展开并高亮定位，可用“上一处 / 下一处”切换。在同一节点定时刷新时，保留搜索、查看方式和展开状态。“复制 JSON”复制当前完整格式化内容。预览最多渲染 2000 个字段，JSON 视图可检索全部已记录内容；采集阶段已经截断的内容不会补造。

## 实时统计

顶部显示选中请求的总 tokens、输入/输出 tokens、输出 TPS、最近一轮首段响应和缓存命中率；模型节点提供单轮统计及生成阶段 TPS。页面每秒更新。

- 用量：结束时采用 Pi 标准化的模型 `usage`。输入展示包含普通输入、缓存读取及缓存写入；思考 tokens 已包含在输出中，不重复相加。
- 实时估算：未收到有效用量时，按流式文本、思考和工具参数粗估输出（ASCII 约 4 字符/token，其他字符约 1 字符/token），显示 `≈`。模型返回正式用量后校准。尚未上报的输入不计入实时总数。
- 输出 TPS：所有已记录模型轮次的输出 tokens，除以模型轮次总耗时。包含首段等待，不含工具执行时间；不会把各轮 TPS 做算术平均。
- 首段响应：从当前轮次开始到第一个内容片段的时间，可能是文字、思考或工具参数，不代表首个可见文字。
- 生成阶段 TPS：输出 tokens 除以首段到末段内容的时间；运行时计算到当前时刻。只有一个内容片段时不计算。它反映客户端收到流式内容的速率。
- 缓存命中：缓存读取 /（普通输入 + 缓存读取 + 缓存写入）。
- 缺少统计的轮次显示 `—`，已知部分显示 `≥`；失败或取消后的零初始化用量不视为正式报告。工具结果中的嵌套用量不重复计入主循环模型统计。

更新扩展后，在 Pi 执行 `/reload`，再打开 `/trace`。旧记录若保留了 `usage`，可计算 tokens 与含等待的 TPS；没有记录流式时间的历史请求不会补造首段响应或生成 TPS。

## 开发检查

```sh
npm install --ignore-scripts
npm run check
node --test test/recorder.test.ts test/server.test.ts
node --test test/metrics.test.ts
node --test test/viewer.test.mjs
node --test test/json-viewer.test.mjs
node --test test/history.test.mjs
node --test test/timeline.test.mjs
```

本地确定性集成测试使用 Pi 官方 faux provider，不调用付费模型：

```sh
node --test test/pi-integration.test.ts
```

`viewer.test.mjs` 在 DOM 环境中验证真实页面脚本的节点切换、源码读取和提问。它不替代真实浏览器的布局检查。终端测试遵循 Pi 的 tmux 流程，测试产物位于 `.test-output/`，使用隔离配置与 faux provider。

卸载 GitHub 安装的扩展时执行 `pi remove git:github.com/tangf-ai/pi-run-trace`；本地安装时使用对应安装路径。历史记录保留。

## 隐私与开源协议

轨迹保存在本机，查看器不将记录上传到远程服务。提示词、工具参数和输出可能包含敏感内容，自动隐藏仅覆盖已知凭证格式，分享记录前请自行检查。“针对这步提问”会把选中节点和关联源码发送到当前 Pi 会话，并由该会话配置的模型处理。

采用 [MIT 协议](LICENSE)。本项目是独立的 Pi 扩展，Pi 本身由 [earendil-works/pi](https://github.com/earendil-works/pi) 维护。
